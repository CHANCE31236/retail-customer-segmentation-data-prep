# retail-customer-segmentation-data-prep

End-to-end **data preparation pipeline in R**: from a messy CRM customer export to a tidy, **segmentation-ready dataset** (Gold / Silver / Bronze retail segments).

Written in the style of a university *Data Preparation* lab session (step-by-step exercises with hints, plus a fully commented solution) - and it doubles as a small **portfolio project** for data analyst / business analytics interviews.

## What this project shows

The complete *profile -> clean -> transform -> segment -> export* workflow:

- Import a CSV with every column as character and empty fields as `NA`
- Profile missing values before touching anything
- Regex cleaning: honorifics, whitespace, phone digits, email validation, country codes
- **Multi-format date parsing** with a reusable base-R helper
- Messy currency to numeric **without data loss** (symbols, separators, negative parentheses)
- Feature engineering: recency / frequency / monetary
- Business rule segmentation (`case_when`) and per-segment summary
- Data-quality audit and clean CSV export with a round-trip check
- A **Confluence-style data preparation specification** (`docs/`) documenting the whole methodology

## Files

| File | Purpose |
|------|---------|
| `exercises.R` | The exercises with hints - try them before peeking |
| `solutions.R` | Fully commented solutions with expected outputs printed |
| `data/customers_raw.csv` | The messy CRM export (24 customers) |
| `data/customers_clean.csv` | Generated by the solution - the tidy output |
| `docs/data-preparation-spec.md` | Confluence-style spec: rules, schema, QA checks |

## How to run

```r
install.packages(c("readr", "dplyr", "stringr"))   # once
source("solutions.R")                               # runs the whole pipeline
```

Requires **R >= 4.0**. The dataset is synthetic; the analysis date is fixed at
`2025-09-30` so results are reproducible.

## Segmentation rule (documented in the spec)

| Segment | Rule (total spend) |
|---|---|
| Gold | >= 3000 |
| Silver | >= 800 |
| Bronze | < 800 |
| Unclassified | missing spend (`n/a`) - flagged for CRM follow-up |

## Learning outcomes (interview talking points)

- The **profile first** habit: count `NA`s before deciding how to clean
- Regex patterns that are safe to run on real data (anchors, character classes)
- Handling **ambiguous date formats** with an explicit, documented convention
- Converting currency strings without losing a single parseable value
- Turning cleaning rules into a **reviewable spec** with acceptance criteria
